# شواهد برامج التوجيه الطلابي
نظام عربي للجوال لإنشاء مجلدات برامج التوجيه الطلابي داخل **Google Drive الخاص بالموجهة**، رفع الشواهد من الكاميرا أو ملفات الجهاز، توليد رموز QR قابلة للطباعة والمشاركة، وتعديل أسماء البرامج وحذفها إلى المهملات.

## ما الذي تم إنجازه؟
- واجهة HTML / CSS / JavaScript متجاوبة للجوال، مستضافة على GitHub Pages عند تفعيلها.
- تسجيل الدخول إلى Google عبر OAuth، باستخدام صلاحية Drive محدودة \`drive.file\`.
- إنشاء مجلد رئيسي جديد «شواهد برامج التوجيه الطلابي» في حساب المستخدم المفوَّض، دون تعديل مجلدات سابقة.
- جعل المجلد الرئيسي متاحًا لأي شخص لديه الرابط كـ«مشاهد»، مع وراثة الصلاحيات في مجلدات البرامج الجديدة.
- إنشاء البرامج / إعادة تسميتها / إرسالها إلى مهملات Drive عند الحذف، بعد تأكيدين.
- تصوير شهادة أو نشاط بالكاميرا، أو رفع صور وPDF ومستندات من الهاتف.
- توليد رمز QR أسود للمجلد الرئيسي وأكواد ملونة لكل برنامج مع شعار وسط الرمز؛ مشاركة الرمز أو الرابط والطباعة على A4/PDF.
- تغيير صورة الشعار، وحفظ إعدادات الألوان والشعار في ملف داخل مجلد Drive الجديد (حتى تظهر في الأجهزة الأخرى).

## تعليمات البدء من الجوال
### 1) تفعيل موقع GitHub Pages (مرة واحدة)
1. افتح [إعدادات المستودع](https://github.com/drburghash-sys/student-guidance-evidence/settings/pages).
2. ضمن **Build and deployment** اختر **Source: Deploy from a branch**.
3. اختر **main** و **/(root)** ثم **Save**.
4. عندما يظهر **Visit site** افتحه. العنوان المتوقع: https://drburghash-sys.github.io/student-guidance-evidence/ (يتطلب النشر والتحقق).

### 2) تجهيز Google Cloud (مرة واحدة)
1. افتح https://console.cloud.google.com/ وأنشئ مشروعًا جديدًا.
2. فعّل **Google Drive API** ضمن APIs & Services.
3. من **Google Auth Platform** جهّز شاشة الموافقة، ثم أنشئ **OAuth Client** من نوع **Web application**.
4. ضع **Authorized JavaScript origin**:
   \`https://drburghash-sys.github.io\`
   (ليس رابط المستودع بكامله).
5. إذا كان التطبيق في وضع **Testing**، أضف البريد الإلكتروني لزوجتك تحت **Test users**.
6. انسخ **Client ID** (ينتهي بـ \`.apps.googleusercontent.com\`) فقط. لا تستخدم Client Secret في الموقع.

### 3) إرسال الرابط للزوجة
1. افتح الموقع من جوالك → **الإعدادات** → ألصق **Client ID** واحفظ.
2. اضغط **مشاركة رابط الإعداد مع الزوجة**. سيفتح على جوالها مع Client ID العام مُجهزًا، ولا يرسل كلمات مرور أو صلاحيات.
3. تفتح الزوجة الرابط من متصفح Chrome وتسجل الدخول **بحساب Google الخاص بها**.
4. تضغط **إنشاء / استعادة المجلد الرئيسي**؛ سيُنشأ في حسابها، ويُضبط «أي شخص لديه الرابط — مشاهد».
5. الآن تضيف البرامج، وتصور الشواهد وترفعها، وتشاهد أكواد QR وتشاركها.

> **تنبيه:** ربط Google Cloud ليس خدمة تخزين؛ التخزين الفعلي يتم في حساب Drive الذي تسجل به الزوجة داخل التطبيق. لا تستخدم حساب الزوج عند إجراء خطوة إنشاء مجلد الشواهد.

## الخصوصية والأمان
- أي ملف داخل مجلد الشواهد **عام لمن لديه الرابط**. لا ترفع أسماء أو صورًا أو بيانات حساسة للطالبات دون موافقة وتصريح مناسبين.
- تطبيق GitHub Pages لا يملك خادمًا خاصًا أو كلمات مرور؛ رموز Google OAuth لا تُخزن في GitHub أو localStorage.
- صلاحيات التعديل تعود إلى حساب Google صاحب المجلد، لا إلى زائر لديه كود QR.
- الملفات التي يزيد حجمها عن 35MB تُرفع يدويًا إلى مجلد البرنامج في Drive، من الرابط الموجود في التطبيق.
- إذا منع حساب Google المدرسي مشاركة «أي شخص لديه الرابط» فلن يستطيع التطبيق تجاوز هذه السياسة.

## ملاحظات تقنية
- يتطلب الاتصال بالإنترنت لتحميل مكتبة Google Identity Services و qr-code-styling.
- الأيقونة مركز QR صغيرة، ومستوى تصحيح الأخطاء مرتفع؛ اختبر رموز QR المطبوعة قبل توزيعها.
- رابط Drive القياسي ليس خدمة تقصير روابط خارجية؛ يمكن مشاركة الرابط المباشر والرمز.
- عند إعادة تسمية البرنامج يظل معرّف Drive وبالتالي رابط QR كما هو.
- عند نقل البرنامج إلى مهملات Drive يتوقف الرمز عن فتحه إلى أن يُستعاد المجلد.
- الكود مفتوح المصدر وغير مخصص لحفظ الحالات الإرشادية الفردية السرية.

## الملفات
- \`index.html\`: واجهة التطبيق
- \`style.css\`: التصميم والتنسيق والطباعة
- \`app.js\`: ربط Drive والرفع والأكواد والإدارة
- \`icon.svg\`, \`manifest.webmanifest\`: هوية الموقع وإضافته للشاشة الرئيسية
